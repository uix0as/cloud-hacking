위 제품의 UI나 자산을 복제하지 않았습니다. 공통 원칙을 비교한 뒤 Boundary만의 관제 워크스페이스로 구성했습니다.

## 최종 방향: 조용한 사고 대응 워크스페이스

- 밝은 회색 바탕과 흰색 패널로 구조를 구분합니다.
- 주황색은 현재 단계와 주요 행동에 사용합니다.
- 짙은 잉크색 터미널로 입력 영역에 시선을 모읍니다.
- 보안 노출은 따뜻한 적색, 보호 상태는 차분한 녹색으로 구분합니다.
- 이모지, 점수, 강의 배지 대신 사건 제목·활동 로그·검증 결과를 사용합니다.
- 직접 만든 서버 일러스트, 연결선, 인프라 노드는 SVG와 CSS로 렌더링합니다.
- 원격 이미지, 유료 폰트, 외부 CDN에 의존하지 않습니다.

## 레이아웃

데스크톱에서는 인프라 맵을 왼쪽, 터미널을 오른쪽에 둡니다. 맵 아래는 사건 맥락, 터미널 아래는 바로 다음 명령과 설명입니다. 화면 폭이 좁아지면 맵 → 터미널 → 입력 안내 → 사건 맥락 순서로 전환합니다.

모바일에서는 내비게이션이 접히며, 터미널 입력 프롬프트와 명령 입력을 두 줄로 분리합니다. 모달은 화면 안에서 스크롤되고 Escape로 닫힙니다. 운영체제의 동작 줄이기 설정도 반영합니다.

## 메시지 원칙

‘클라우드니까 안전하다’는 문구를 쓰지 않습니다. 장소가 아니라 인증과 권한 설정이 보안 경계를 만든다는 내용을 일관되게 전달합니다. 전문 용어는 출입증, 보관함, 마스터키처럼 익숙한 비유로 설명하되 실제 기술 의미와 한계를 함께 적습니다.
