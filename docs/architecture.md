# 아키텍처

## 데이터 흐름

```text
사용자 입력
  → React 입력줄 / xterm.js 출력
  → 실행 어댑터
      ├─ 기본 모드: TypeScript 상태 엔진 → 브라우저 저장
      └─ 서버 모드: Vite /api 프록시 → Spring Boot → HTTP 세션
  → 단계·출력·이벤트를 담은 응답
  → 인프라 맵 / 진행률 / 리포트 갱신
```

두 엔진은 같은 `shared/scenario.json` 파일을 사용합니다. Java 빌드가 이 파일을 클래스패스 리소스로 복사합니다. 명령, 응답, 단계 문구를 두 곳에서 따로 작성하지 않습니다.

## 세션 상태

- `version`: 저장 형식 버전
- `step`: 다음 명령의 인덱스, 0부터 12까지
- `entries`: 최근 100개의 출력 항목
- `events`: 성공적으로 진행한 단계의 이벤트
- `startedAt`: 시작 시간

브라우저 저장이 비활성화되어도 임시 세션으로 계속 실행합니다. 잘못된 저장 형식은 초기 상태로 복구합니다. 서버 모드에서는 브라우저 저장을 사용하지 않고 서버의 세션을 조회합니다. 네트워크 오류 때 로컬 모드로 몰래 전환하지 않습니다.

## API

| 메서드 | 경로                 | 동작                                       |
| ------ | -------------------- | ------------------------------------------ |
| GET    | `/api/session`       | 현재 세션 조회 또는 생성                   |
| POST   | `/api/command`       | 현재 단계에 맞는 명령을 검증하고 결과 반환 |
| POST   | `/api/session/reset` | 현재 세션 초기화                           |

POST 요청은 `Content-Type: application/json`을 사용합니다. 명령 요청 예:

```json
{ "command": "help", "expectedStep": 0 }
```

응답은 `state`, `accepted`, 선택적인 `message`를 포함합니다. 보조 명령은 출력을 바꾸지만 `accepted`는 false이며 단계가 진행되지 않습니다.

- 400: 누락된 필드, 잘못된 인덱스, 256자를 넘는 입력
- 409: 다른 창에서 이미 진행되어 예상 단계가 달라진 경우
- 415: JSON이 아닌 POST 요청

세션별 상태 변경은 동기화합니다. 명령 중복 실행 방지를 위해 프런트엔드에서도 진행 중 제출을 막습니다.

## 실행 경계

문자열 일치와 고정 응답만 사용합니다. 셸 프로세스 실행, 사용자 지정 네트워크 요청, 파일 경로 해석은 없습니다. 실습 비밀번호는 출력 이력에 마스킹해서 저장합니다. 서버 세션 쿠키는 HttpOnly와 SameSite=Strict를 사용하고 서버는 기본적으로 loopback 주소에서만 수신합니다.

인증된 운영 서비스가 아닌 로컬 실습 환경입니다. 인터넷 배포에는 별도의 사용자 인증, 요청 보호, 저장 정책, TLS와 운영 설정이 필요합니다.

## 제한

브라우저 모드의 상태는 사용자가 변경할 수 있으므로 평가나 인증서 발급에 사용할 수 없습니다. 서버 세션도 재시작 시 사라집니다. IAM 정책 결과는 정해진 시나리오이며 실제 AWS의 모든 정책 결합과 예외를 계산하지 않습니다.
