# Boundary

**하나의 열쇠가 유출된 밤.** 직접 명령을 입력하고 인프라의 변화를 관찰하는 클라우드 보안 시뮬레이션입니다.

강의 목록 대신 사고 대응 워크스페이스를 제공합니다. 가상의 서버 사고를 확인하고, 파일을 클라우드 보관함으로 옮기고, 최소 권한과 추가 인증을 설정한 뒤 접근 결과를 비교합니다.

## 빠른 실행

Node.js 22 이상을 권장합니다. 모든 명령은 이 저장소 루트에서 실행합니다.

```bash
npm ci
npm run dev
```

브라우저에서 <http://127.0.0.1:5173>을 엽니다. 다른 프로그램이 해당 포트를 쓰면 터미널에 표시된 주소를 사용합니다.

기본 모드는 브라우저 안에서 동작하며 진행도를 해당 브라우저에 저장합니다. 계정, API 키, 데이터베이스, Docker, 클라우드 가입이 필요 없습니다.

## Spring Boot와 함께 실행

Java 17 이상이 설치되어 있어야 합니다.

```bash
npm ci
npm run dev:full
```

실행 스크립트가 다음 작업을 수행합니다.

1. 무료 Maven 배포본의 체크섬을 검증하고 `.tools`에 준비합니다.
2. 프로젝트 안의 `.tools/m2`에 Java 의존성을 저장하고 백엔드를 빌드합니다.
3. `127.0.0.1:8080`에서 Spring Boot를 실행합니다.
4. 프런트엔드를 실행하고 `/api` 요청을 백엔드에 전달합니다.

이 모드에서는 서버가 명령 순서와 진행도를 검증합니다. 브라우저별 HTTP 세션으로 상태를 분리하고, 서버 재시작 또는 2시간의 비활동 후 세션이 초기화됩니다. 브라우저 전용 모드의 진행도와 서버 모드의 진행도는 별개입니다. 종료는 `Ctrl+C`입니다. 서버 로그는 `.tools/backend.log`에서 확인합니다.

두 모드를 동시에 같은 포트에서 실행하지 마세요. 별도 실행도 가능합니다.

```bash
npm run backend:run
# 별도 터미널
VITE_SESSION_MODE=server npm run dev
```

최초 패키지 설치에는 인터넷이 필요합니다. 설치 후 시뮬레이션은 외부 서비스 없이 실행됩니다. 클라우드 리소스를 생성하거나 사용량에 따라 요금을 청구하는 기능은 없습니다.

## 경험 흐름

| 단계                 | 사용자 행동                                         | 핵심 내용                                       |
| -------------------- | --------------------------------------------------- | ----------------------------------------------- |
| 작은 틈, 큰 사고     | 가상의 유출 계정으로 접속하고 권한·자산 확인        | 비밀번호 단독 인증과 과도한 권한의 위험         |
| 데이터의 새로운 경계 | 가상 S3 보관함 생성, 백업, 권한·추가 인증 조건 적용 | 이전뿐 아니라 접근 규칙 설계가 필요             |
| 같은 시도, 다른 결과 | 서버 비밀번호, 제한된 세션, 정상 세션 비교          | 인증과 권한은 다르며, 필요한 접근만 허용해야 함 |

클라우드가 자동으로 모든 공격을 막는다고 설명하지 않습니다. 온프레미스에도 다중 인증과 권한 분리를 적용할 수 있습니다. 서버 로그인 비밀번호는 AWS 인증 정보와 별개입니다. MFA 활성화만으로 모든 API 요청이 차단되는 것도 아니므로 이 실습에서는 MFA 인증 세션을 요구하는 정책 조건까지 설정합니다.

## 주요 기능

- xterm.js 출력과 리눅스 스타일 입력줄
- 회색 명령 가이드 위에 따라 입력하는 Shadow Typing
- 오타 안내, 입력 보조, 비밀번호 마스킹, `help` / `pwd` / `clear`
- 단계별 인프라 맵과 접근 노출·차단 상태
- S3, IAM, MFA 등 노드를 눌러 읽는 쉬운 개념 설명
- 활동 기록, 초기화 확인, 진행도 복원
- 완료 전후 비교 리포트와 텍스트 다운로드
- 모바일 레이아웃, 키보드 조작, 동작 줄이기 설정

## 시뮬레이션의 범위

터미널 입력은 정해진 명령 목록과 비교될 뿐, 운영체제 셸에서 실행되지 않습니다. 네트워크 접속, SSH 실행, 실제 파일 읽기, AWS SDK 호출은 없습니다. `.invalid` 주소와 모든 계정·데이터는 가상입니다. `lab`으로 시작하는 명령은 이 프로젝트 전용이며 AWS CLI 명령이 아닙니다.

클라우드 맵의 EC2는 아키텍처 설명용 참고 노드입니다. 실제 EC2를 만들거나 과금하지 않습니다. IAM/MFA 정책도 시나리오의 고정된 상태 전이로 표현하며 범용 AWS 정책 평가기를 구현하지는 않습니다.

로컬 사용을 대상으로 하며, 공용 인터넷 배포용 인증·영구 저장·운영 모니터링은 포함하지 않습니다.

## 검증

```bash
npm test
npm run backend:test
npm run build
npm run format:check
```

프런트엔드 상태 엔진의 전체 흐름, 명령 순서, 잘못된 입력, 비밀번호 마스킹, 보조 명령과 이력 제한을 검증합니다. 백엔드는 전체 시나리오, 세션 분리, 초기화, 요청 유효성, 오래된 진행도의 충돌 처리를 통합 테스트합니다.

수동 화면 검증 기록은 [docs/verification.md](docs/verification.md)를 참고하세요.

