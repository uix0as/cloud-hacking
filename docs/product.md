# Boundary 제품 기획

## 목표

클라우드와 리눅스를 처음 접하는 사용자가 약 5분의 사건 시뮬레이션을 통해 인증, 권한, 보호 설정의 중요성을 설명할 수 있게 합니다.

## 핵심 경험

사용자는 사건 대응 워크스페이스를 열고 바로 첫 명령을 입력합니다. 가상 서버의 인증 실패 구조를 관찰한 뒤 대응자로 시점을 바꿔 백업과 보호 설정을 수행합니다. 마지막에는 외부 접근과 정상 업무 접근을 비교합니다.

현재 시나리오는 3개 단계와 12개 명령으로 구성합니다. 로그인, 회원가입, 결제, 점수 경쟁을 도입하지 않습니다.

## 검증 가능한 완료 조건

1. 유출된 비밀번호가 어떤 설정에서 과도한 권한으로 이어지는지 확인한다.
2. S3의 버킷과 객체를 보관함과 파일로 이해한다.
3. 최소 권한과 추가 인증 조건을 설정한다.
4. 서버 비밀번호와 클라우드 인증 정보가 다름을 확인한다.
5. 유효한 세션이 있어도 허용되지 않은 작업은 차단됨을 확인한다.
6. 허용된 역할과 인증을 갖춘 정상 사용자는 필요한 작업을 수행한다.
7. 리포트에서 이전과 이후의 접근 범위를 비교한다.

## 내용의 정확성

- 현재의 온프레미스 서버는 의도적으로 잘못 설정된 가상 사례입니다. 온프레미스 전체의 특성이 아닙니다.
- S3가 모든 방식의 접근에서 MFA를 자동 요구하지 않습니다. 실습의 정책 조건으로 요구합니다.
- `lab` 명령은 고정된 실습 상태를 바꾸는 표현입니다. 실제 관리 명령과 구분해서 안내합니다.
- 제한된 클라우드 세션은 시나리오가 제공하는 테스트 신원입니다. 인증 정보를 획득하는 절차는 없습니다.
- 파일 이름과 백업 출력은 합성 데이터입니다.

## 범위

포함: 단일 시나리오, 쉬운 설명, 상태 기반 맵, 가상 터미널, 진행도, 로그, 결과 리포트, 두 가지 실행 모드.

향후 확장: 추가적인 방어 시나리오, 여러 언어, 서버 영구 저장, 접근성 추가 검증. 시나리오 원본은 `shared/scenario.json`으로 분리해 문구와 단계를 함께 관리합니다. 단계 개수 변경 시 UI의 진행률·리포트·단계별 개수도 함께 수정해야 합니다.
